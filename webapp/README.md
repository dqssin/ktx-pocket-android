# Docker 웹 버전

윈도우에서 Docker 컨테이너를 실행하고 브라우저의 [localhost:8765](http://localhost:8765)로 조작합니다. 브라우저 탭과 별도로 예약 작업이 실행됩니다.

## 실행

Docker Desktop을 Linux 컨테이너 모드로 실행한 뒤, 저장소 폴더에서 다음 명령을 실행합니다.

```powershell
docker compose up -d --build
```

브라우저에서 **http://localhost:8765**를 엽니다. `-d`로 실행하므로 터미널이나 브라우저를 닫아도 검색은 계속됩니다. PC·Docker가 실행 중이어야 하며 절전·종료·컨테이너 중단 시 검색도 중단됩니다.

기본 포트는 8765입니다. 바꾸려면 루트의 `.env.example`을 `.env`로 복사해 `KTX_WEB_PORT` 값을 수정한 뒤 다시 실행합니다. 다른 프로그램의 포트를 빼앗거나 해당 프로그램을 종료하지 않습니다.

## 사용

1. 출발역·도착역·날짜·시간·인원·좌석 종류와 코레일 계정을 입력합니다. 모든 시각은 한국시간 기준입니다.
2. 다른 날짜·시간도 괜찮다면 ‘추가 조건’에서 현재 조건을 추가한 뒤 입력란을 바꿉니다. 직접 추가할 수 있는 조건은 2개이며 현재 입력값을 포함해 최대 3개입니다.
3. 다른 출발역도 검색하려면 ‘출발역 대안’을 켜고 같은 출발지에서 각 역까지 걸리는 시간을 입력합니다. 현재 출발역을 포함해 1~3개 역을 등록합니다. 직접 등록한 조건을 우선하고 남는 자리에 허용 이동 시간 안의 역을 추가합니다. 지도·실시간 교통은 계산하지 않습니다.
4. ‘검색 시작’을 누르면 실제 조회 전에 최종 조건 목록을 표시합니다. 목록과 개인용 이용 조건을 확인한 뒤 ‘위 조건으로 시작’을 누릅니다. 확인되지 않은 조건은 예약하지 않습니다.
5. 조회 상태·횟수·최근 기록은 오른쪽 상태 영역에서 확인합니다. 예약 1건을 확보하면 모든 검색을 종료하며, 결제는 코레일톡에서 직접 진행합니다.
6. 검색 중에는 ‘검색 중지’를 누릅니다. 이미 전송한 예약 요청은 결과를 확인하기 전까지 되돌릴 수 없으므로, 처리 중이던 예약이 있다면 코레일톡 예약내역을 확인합니다.
7. 예약 성공 또는 결과가 불확실한 경우 예약내역 확인을 마쳐야 새 검색을 시작할 수 있습니다. ‘확인 완료’는 이 앱의 확인 상태만 해제하며 실제 결제·취소 요청을 보내지 않습니다.

**이 버전은 결과를 웹 화면에서 확인합니다. 텔레그램 전송·브라우저를 닫은 상태의 외부 알림·안드로이드의 결제 재알림은 포함하지 않습니다.**

## 유지되는 제한

- 로그인·조회·예약 요청은 같은 대기 제한을 공유합니다. 이전 요청 완료 후 3~5초 대기하며 간격을 줄이는 설정은 없습니다.
- 최대 3개 조건을 순서대로 확인하고 예약 1건 후 종료합니다. 한 컨테이너에서 검색은 하나만 실행합니다.
- 조회 통신 오류는 30·60·120·120초 대기하고, 5회 연속 실패하면 중지합니다. 접속 제한과 HTTP 403·429는 자동 재시도하지 않습니다.
- 예약 결과가 불확실할 때 다시 예약하지 않고 중지합니다. 이동·승차 여유는 실제 예약 요청을 보내기 직전에도 다시 확인합니다.
- 1회 최대 5시간 45분입니다. 서버나 PC를 다시 시작해도 이전 검색을 자동 재개하지 않습니다.

## 저장과 접근

- 웹 포트는 `127.0.0.1`에만 연결합니다. 같은 PC의 `localhost`로 접속하며 외부나 다른 휴대폰에는 공개하지 않습니다.
- 최근 검색 조건, 예약 결과, 기기 식별자는 `ktx-data` Docker 볼륨에 저장합니다. 컨테이너를 다시 만들어도 유지됩니다.
- 아이디·비밀번호 저장은 선택 사항이며 기본값은 꺼짐입니다. 선택한 정보는 AES-256-GCM으로 저장하고, 비밀번호를 상태 응답이나 브라우저에 다시 내려보내지 않습니다.
- 암호화 키도 같은 Docker 볼륨에 저장됩니다. Android Keystore처럼 별도 하드웨어로 보호하는 방식은 아니며, 호스트 관리자나 볼륨 전체에 접근할 수 있는 사용자는 복호화할 수 있습니다. 이 PC와 Docker 저장 공간을 보호해야 합니다.
- ‘저장된 로그인 정보 삭제’는 저장한 계정만 지우며 실행 중인 검색이나 기기 식별자를 바꾸지 않습니다. Docker 볼륨 삭제는 기기 식별자와 예약 결과까지 지우므로 별개입니다.
- 다른 사이트에서 명령을 보내지 못하도록 요청 출처·Host·페이지 확인 토큰을 검증합니다. 공개 서버나 다중 사용자 서비스로 사용하도록 만든 버전은 아닙니다.

## 중지와 업데이트

검색을 중지하고 처리 중인 예약내역을 확인한 뒤 업데이트합니다.

```powershell
git pull
docker compose up -d --build
```

서비스 중지:

```powershell
docker compose stop
```

`docker compose down`도 저장 볼륨은 유지합니다. 실제 예약의 취소는 코레일톡에서 진행합니다.

## 검사

```powershell
docker compose build
docker run --rm --network none --read-only --tmpfs /tmp --entrypoint python ktx-pocket-web:local -m unittest discover -s tests -v
```

외부 통신을 차단하고 가짜 응답으로 검색·예약 결과와 웹 실행 흐름을 검사합니다. 실제 코레일 로그인·조회·예약 성공을 확인한 검사는 아닙니다.

구현 시 Python 검사 46개와 기존 Android Java 검사 15개, Android APK 빌드를 통과했습니다. 실제 Docker 컨테이너의 실행·상태 응답·저장 권한과 브라우저의 조건 확인·추가 조건·역 이동 시간 입력 화면을 확인했습니다.

통신에는 안드로이드 앱과 같은 `pykorail 0.5.1`을 사용합니다. Docker에서는 라이브러리의 데스크톱 통신을 사용하며 기기 인증·서명 방식은 수정하지 않습니다. 배포 wheel과 원본 라이선스는 [vendor](vendor/README.md)에 있습니다. 개인용·비상업적 이용 조건을 유지해야 합니다.
